### 发现的问题

#### 1. 【中】定时签到未跳过黑名单成员
**文件**: `sign/index.py:50-57`
```python
def run_daily_sign():
    users = oss_store.get_users()  # 只读了名册
    for u in users:
        openid = u.get("openid")
        # ... 签到逻辑
```
**问题**: 定时签到遍历 `users.json`，但拉黑的人已经从 `users.json` 移到 `blacklist.json`，所以**已经自动跳过**。但代码缺少显式注释说明这一点，容易被误解为"需要额外判断黑名单"。

**建议**: 加注释说明跳过逻辑依赖"拉黑 = 移出名册"的设计。

---

#### 2. 【低】`member_id` 哈希碰撞风险未文档化
**文件**: `sign/oss_store.py:27-31`
```python
def member_id(openid, nickname=""):
    if openid:
        return "o" + hashlib.sha256(openid.encode("utf-8")).hexdigest()[:12]
    return "n" + hashlib.sha256(("nick:" + nickname).encode("utf-8")).hexdigest()[:12]
```
**问题**: SHA256 前 12 位理论上有碰撞风险（~2^48 空间），但当前场景（几十人）实际无风险。缺文档说明碰撞处理策略。

**建议**: 加注释说明"当前规模碰撞概率可忽略；若扩展到数千人需改用完整哈希或 UUID"。

---

#### 3. 【低】黑名单操作代码重复
**文件**: `sign/oss_store.py:129-165`

三个函数 `move_to_blacklist` / `restore_from_blacklist` / `delete_from_blacklist` 都有相似的"遍历查找 mid"逻辑：
```python
target = next((b for b in bl if member_id(...) == mid), None)
```

**建议**: 抽取 `_find_by_id(collection, mid)` 辅助函数减少重复。

#### 4. 【低】错误处理不一致
**web.py** 的 JSON 解析都用了 try-except 并返回 400，但 **oss_store.py** 的 OSS 读写操作没有异常处理（假设 OSS SDK 抛出异常会直接传播到 FC）。

**建议**: 
- oss_store 的 `_read_json` / `_write_json` 加异常捕获，返回空列表/False，避免整个函数挂掉
- 或在 web.py 的路由层统一 try-except 捕获 500 错误

#### 6. 【低】Magic Number：日历窗口 185 天

#### 7. 【低】前端时间每分钟才更新，秒数不动
**文件**: `sign/static/app.js:368`
```javascript
setInterval(load, 60000);  // 每分钟重新加载数据
```
**问题**: 你刚改的时间格式显示到秒（`16:23:45`），但 `load()` 每分钟才调用一次，所以秒数会卡住 60 秒。

**建议**: 
- **方案 A**（推荐）：拆分"时间显示"和"数据刷新"，时间每秒更新（轻量），数据每分钟拉取
- **方案 B**：时间格式改回"不显示秒"，避免用户觉得"卡了"

## 三、安全性 ✅ 基本合格，2 处可加固

### 已实现的安全措施
- ✅ 密码在环境变量，不硬编码
- ✅ 令牌用 SHA256 派生，不直接传密码
- ✅ 写操作需令牌验证（`_check_token`）
- ✅ openid 不在任何响应中回显给前端
- ✅ `member_id` 哈希不可逆推 openid
- ✅ 使用 `hmac.compare_digest` 防时序攻击

### 待加固项

#### 12. 【中】令牌无过期时间，永久有效
**文件**: `sign/web.py:27-30`
```python
def _make_token():
    raw = f"{ADMIN_USER}:{ADMIN_PASS}:dorm-sign-admin"
    return hashlib.sha256(raw.encode("utf-8")).hexdigest()
```
**问题**: 令牌是密码的纯函数，只要密码不变，令牌永久有效。若令牌泄露（浏览器控制台被看到、网络抓包），攻击者可一直用。

**建议**: 
- **方案 A**（简单）：令牌加入时间戳（精确到小时），1 小时后失效
  ```python
  def _make_token():
      hour = time.strftime("%Y%m%d%H")  # 当前小时
      raw = f"{ADMIN_USER}:{ADMIN_PASS}:{hour}:dorm-sign"
      return hashlib.sha256(raw.encode("utf-8")).hexdigest()
  ```
  验证时同时检查当前小时和前一小时的令牌（容忍 1 小时内的时钟漂移）

- **方案 B**（标准）：用 JWT，设置 `exp` 过期时间

---

#### 13. 【低】CORS 未配置，公网部署后可能被跨域滥用
**现状**: `web.py` 的 `_resp` 函数没有设置 CORS 头，FC 默认不限制跨域。

**风险**: 若看板部署到公网，其他网站的 JS 可以调你的 API（浏览器 CORS 策略不拦截匿名 GET，且 POST 可以用 `no-cors` 模式发）。

**建议**: 
- 读接口（/api/members、/api/blacklist）可以匿名，不用 CORS 限制
- 写接口（/api/blacklist/*）已经有令牌保护，CORS 不是主要防线
- 但建议加 `Access-Control-Allow-Origin: https://你的域名`，限制来源（公网部署后再加）
