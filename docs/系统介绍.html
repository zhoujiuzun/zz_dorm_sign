⏰ 自动签到流程（每晚 21:00-22:20）

系统每分钟自动触发，根据专属时刻算法为每个用户在 81 分钟窗口内分配唯一签到时间

核心步骤详解

  • 定时触发
    两个定时器：H21 (21:00-21:59 每分钟) 和 H22 (22:00-22:20 每分钟)，共 81 次/晚
  • 读取用户名册
    从 OSS 读取 users.json，获取所有需要签到的用户（黑名单用户已移除）
  • 计算专属时刻
    target_minute = SHA256(openid:日期) % 81 + 1260
    1260 = 21:00，81 = 窗口长度，确保同人同天固定、人人不同
  • 筛选匹配用户
    只签"专属时刻 = 当前分钟"的人，大多数分钟无人匹配，直接退出
  • 执行签到链路
    登录 → 获取任务 → 获取坐标 → 计算距离 → 提交签到（每步都有错误处理）
  • 记录结果
    成功/失败都写入 history.json，但只有失败才推送 Server酱通知
🎯 为什么使用专属时刻算法？
如果 10 个人在 21:00:00 同时签到，学校系统可能判定为异常行为触发风控。专属时刻算法将每个人分散到 81 分钟窗口内（21:00-22:20），每人每天有唯一时刻，避免同时签到。
⚠️ 重要特性：
• 不轮询、不复查 - 每人每天只在专属那一分钟签一次
• 无自动补签 - 如果那一分钟失败了，当天就漏了（会推送告警）
• 成功静默 - 只有失败才推送通知，避免每天 10 条消息轰炸
• 同分钟多人 - 添加 0-3 秒随机延迟错开请求

👤 用户注册流程（首次加入系统）

新用户需要在 PC 微信上通过采集工具抓取 openid，每人只需操作一次

详细步骤

  • 运行采集工具
    双击 openid-capture.exe，工具自动安装 mitmproxy 证书并开启系统代理
  • PC 微信登录小程序
    必须在 PC 微信上登录"平安打卡"小程序（安卓 7+ 不信任用户证书，无法抓手机微信）
  • 自动抓取 openid
    工具拦截 getOpenidByJsCode 响应，提取 openid（永久凭据，一辈子不变）
  • 自动注册
    工具自动调用 FC /register 接口，后端用 openid 登录学校系统验证有效性
  • 获取真实姓名
    后端调用 login_via_openid 返回 userName，自动入库，无需手动输入昵称
  • 清理环境
    注册完成后，工具自动删除证书、关闭系统代理，恢复正常网络
⚠️ 重要注意事项：
• 必须用 PC 微信 - 手机微信无法 MITM，抓不到 openid
• 需要注册密码 - 找管理员获取 REGISTER_SECRET（防止陌生人滥用）
• 只需操作一次 - openid 永久有效，注册后每天自动签到
• 如已登录先退出 - 小程序已登录时不会发起 getOpenidByJsCode 请求
🔐 为什么要抓 openid？
openid 是微信小程序的用户唯一标识，永久不变，是唯一能让服务器"假装是你"登录学校系统的凭据。它只在小程序登录瞬间的一个接口里出现，无法通过其他方式获取，所以必须用 MITM 抓包。

🔧 管理员操作流程

管理员可以管理用户、控制签到开关、查看所有人状态

管理操作详解

🚫 拉黑用户

效果：暂停该用户的自动签到
操作：从 users.json 移到 blacklist.json
可逆：是，可以随时恢复
历史记录：保留

✅ 恢复用户

效果：恢复自动签到
操作：从 blacklist.json 移回 users.json
立即生效：下次签到窗口开始自动签到
历史记录：完整保留

🗑️ 永久删除

效果：彻底清除用户数据
操作：从 users.json 软删除到 deleted.json（可自助恢复）
不可逆：无法撤销，需重新注册
历史记录：保留但无法关联

⏸️ 全局控制

效果：一键暂停所有人签到
操作：修改 settings.json 的 signing_enabled
场景：放假期间、系统维护
恢复：再次点击开启

管理员权限控制

  • 登录验证
    账号密码存储在 FC 环境变量（ADMIN_USER / ADMIN_PASS），使用 HMAC-SHA256 签发不透明令牌
  • Token 有效期
    令牌按自然小时签发，校验时容忍前一小时（约 1-2 小时有效，避免整点失效）
  • 操作鉴权
    所有管理操作都需要携带 token，后端验证签名和过期时间
  • 操作日志
    暂无，建议未来添加操作审计日志（谁在什么时间操作了谁）
⚠️ 安全注意：
• 永久删除不可逆 - 删除前请确认，用户需重新注册
• 管理员密码强度 - 建议使用强密码，存储在环境变量中
• Token 泄露风险 - 1 小时内有效，避免在不安全设备上登录
• 拉黑 vs 删除 - 优先使用拉黑，删除仅用于彻底清除数据

💡 核心技术特性

系统采用多项技术手段确保签到成功率、隐私安全和系统稳定性

🎯 专属签到时刻算法

公式：
target = SHA256(openid:日期) % 81 + 1260

特性：
• 同人同天固定时刻
• 不同人分散在 81 分钟窗口
• 每天变化，避免固定模式
• 时刻范围：21:00-22:20

效果：避免全员同时签到触发风控

📍 坐标智能抖动

获取真实坐标：
从 getTaskByIdForApp 返回的 dormitoryRegisterVO.locationLat/lng 获取（每人不同）

随机抖动：
±0.00003 度（约 ±3 米）模拟真实 GPS 漂移

距离计算：
使用 haversine 公式计算真实距离填入 locationAccuracy

效果：模拟真实手机签到行为

🌐 DNS 绕过（DoH）

问题：
FC 容器内 DNS 无法解析 simp.csuft.edu.cn（.edu.cn 域名）

解决方案：
• 使用阿里云 DoH (223.5.5.5)
• HTTPS 直连 IP，无需 DNS
• monkeypatch socket.getaddrinfo
• 写死 218.76.12.57 兜底

效果：透明访问学校服务器

🔐 隐私保护机制

member_id：
SHA256(openid)[:12] 作为前端标识

数据分离：
• users.json 含 openid（仅后端）
• history.json 无 openid（可展示）

访问控制：
• OSS Bucket 私有
• RAM 角色内网访问

效果：前端不暴露 openid

⏱️ 高效调度算法

每分钟触发：
定时器每分钟触发，但大多数分钟无人匹配，直接退出

按需执行：
只签"专属时刻 = 当前分钟"的人

并发控制：
同分钟多人添加 0-3 秒随机延迟

效果：降低 FC 超时风险

📬 智能通知策略

成功静默：
签到成功不推送通知，避免每天轰炸

失败告警：
仅失败/异常才推送 Server酱

通知内容：
姓名、时间、状态、错误详情

效果：管理员只需关注异常

🔧 进程内 mitmproxy

设计：
采集工具使用 DumpMaster（不依赖外部 mitmdump）

自动化：
• 自动装/删证书
• 自动开/关系统代理
• 直连上报（绕开代理）

效果：打包后可正常运行

🔑 请求签名算法

学校 API 签名：
FlySource-sign 头部防篡改

算法：
MD5(path + "?sign=" + MD5(timestamp + token))

管理员令牌：
HMAC-SHA256 对（账号:小时）签发不透明令牌，TOKEN_SECRET 仅存环境变量

效果：源码泄露也无法伪造

🏆 技术亮点总结：
通过专属时刻算法、坐标抖动、DNS 绕过、隐私保护等技术手段，系统成功实现了自动化、安全、稳定、低成本的自动签到服务。每项技术都针对实际问题精心设计，确保系统在长期运行中的可靠性。

📡 API 端点总览

后端提供的所有 HTTP API 接口，分为公开端点和管理员端点

🌐 公开端点（无需认证）

POST /register

功能：新用户注册
参数：{openid, register_secret}
验证：校验 secret，用 openid 登录学校系统验证有效性
返回：{created: true, nickname}
调用者：采集工具 openid-capture.exe

GET /api/user

功能：普通用户查看自己的签到记录
参数：?name=姓名
返回：该用户的签到历史和日历数据
隐私：不返回 openid，只返回 member_id
调用者：前端看板（普通用户模式）

🔐 管理员端点（需要管理员令牌）

POST /api/login

功能：管理员登录
参数：{user, password}
验证：对比环境变量 ADMIN_USER / ADMIN_PASS
返回：{token: "..."}（约 1-2 小时有效）
签名：HMAC-SHA256，密钥 TOKEN_SECRET

GET /api/members

功能：查看所有用户的签到状态
参数：无（Header 携带 token）
返回：成员列表 + 总览统计 + 专属签到时刻
数据源：users.json + history.json
调用者：前端看板（管理员模式）

GET /api/blacklist

功能：查看黑名单
参数：无（Header 携带 token）
返回：被拉黑用户列表 + 拉黑时间
数据源：blacklist.json
调用者：前端看板（管理员模式）

POST /api/blacklist/add

功能：拉黑用户
参数：{token, id: member_id}
操作：从 users.json 移到 blacklist.json
效果：停止自动签到，可恢复
调用者：前端看板（管理员点击拉黑按钮）

POST /api/blacklist/restore

功能：恢复被拉黑用户
参数：{token, id: member_id}
操作：从 blacklist.json 移回 users.json
效果：恢复自动签到
调用者：前端看板（管理员点击恢复按钮）

POST /api/member/delete

功能：永久删除黑名单用户
参数：{token, id: member_id}
操作：从 users.json 软删除到 deleted.json（可自助恢复）
警告：不可逆，需重新注册
调用者：前端看板（管理员点击删除按钮）

POST /api/signing

功能：全局启用/停止自动签到
参数：{token, enabled: true/false}
操作：修改 settings.json 的 signing_enabled
效果：一键暂停所有人签到（放假/维护）
调用者：前端看板（管理员点击控制开关）

🌐 Base URL： https://你的函数地址.cn-beijing.fcapp.run
这是阿里云 FC 的临时域名，无需备案，但浏览器直接访问会强制下载而非渲染页面。
部署后替换为你自己的函数地址。
🔒 安全机制：
• CORS 支持：FC HTTP 触发器自带 CORS（回显 Origin），web.py 不再手动添加
• Token 验证：管理员端点用 HMAC 比对令牌（容忍前一小时，恒定时间比较）

• 错误处理：所有接口统一返回 {error: "..."} 格式
