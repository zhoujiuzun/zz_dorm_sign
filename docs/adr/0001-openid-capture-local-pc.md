# 1. OpenID 采集采用"各自本地 PC 抓包"

日期: 2026-06-17

## 状态

已接受

## 背景

系统代表一个用户的唯一凭据是 OpenID。OpenID 不存在于小程序本地，只在用户走
微信登录、后端 `getOpenidByJsCode` 返回时出现在一条 HTTPS 响应里。要拿到它，
必须用 mitmproxy 解密该响应。受众为"自己 + 少数熟人"，全部使用安卓手机。

候选方案：

- **乙 公网代理集中采集**：熟人手机代理指向服务器 mitmproxy，自动入库。
- **甲-集中 本地集中采集**：熟人微信扫码登录运营者 PC，运营者统一抓。
- **甲-各自 本地分布采集**：每个熟人在自己 PC 上抓，工具自动上报 OpenID。
- **丙 不抓包**：复用 jsCode 换 OpenID。

## 决策

采用 **甲-各自**：每个熟人在自己电脑上运行采集工具（mitmproxy + 证书 + 系统代理），
用电脑版微信打开小程序，工具截获 OpenID 后直接 POST 到网站接口入库。

## 理由

- **安卓证书墙**：Android 7+ 默认不信任用户安装的 CA 证书，微信流量在未 root 的
  安卓上无法 MITM。因此 OpenID 必须在 **PC 微信**上采集，乙（依赖安卓手机配代理+信任
  证书）直接不可行。
- **隐私**：甲-各自不要求熟人把微信登录到运营者的电脑，优于甲-集中。
- **基础设施成本**：乙需要常驻公网代理 → 必须 VPS，且是开放中继的安全风险；甲在本地
  一次性运行，永久在线的只剩"注册接口 + 每日定时器"，可放低成本 Serverless。
- **丙** 的 jsCode 绑定微信端，无法在 WeChat 之外独立获取，未能绕开抓包。

## 后果

- 每个熟人需一次性完成"装 mitmproxy 证书 + 配系统代理 + PC 微信抓一次"，门槛较高，
  必须配傻瓜文档/一键工具降低成本。
- OpenID **永久不变、不会失效**，故采集一辈子只需一次，无需重抓机制。这是"输入一次、
  永久自动签"成立的根基。
- 采集工具直接上报 OpenID，避免人工复制长串字符出错。

## 备选方案：读本地存储（已排除）

考虑过不抓包、直接读电脑版微信的小程序本地存储文件来拿凭据。经核对解包源码
（`app-service.js` 的 `setLoginInfo`）：登录后仅 `access-token`（短命 access_token）
和 `userInfo` 落盘，**OpenID 与 refresh_token 均不落盘**——OpenID 只在登录瞬间从
`getOpenidByJsCode` 响应流过内存。故读磁盘只能得到很快过期的 access_token，无法满足
"输入一次、永久自动签"。**OpenID 在物理上只能从网络响应截获**，抓包不可避免。

## 实现要点：证书静默安装

杀软关闭后，以管理员权限将 mitmproxy CA 装入 **LocalMachine 根证书库**（而非
CurrentUser），Windows 不弹安全确认框，可全自动安装。采集完成后工具应自动撤销系统
代理并删除该证书，不把熟人电脑长期留在可被中间人监听的状态。
